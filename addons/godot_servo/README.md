# godot_servo addon

A GDExtension that embeds [Servo](https://servo.org/), the Rust browser engine, into Godot 4 and hands rendered pages to Godot as GPU textures. It automatically registers the `ServoWebView` node and the `ServoServer` engine singleton, so there is no editor plugin to activate and nothing to enable in Project Settings -> Plugins.

For feature overview, full API documentation, and platform-specific details, see the main repository README:
<https://github.com/shiena/godot-servo#readme>

## Helpers

This addon includes helper scripts for common tasks so you don't have to reinvent the wheel. Note that none of these scripts declare a `class_name`: the global class cache is generated by the editor and is absent in headless checkouts that have only run `--import`, which would cause scripts referencing missing global classes to fail parsing. Load them directly via `preload("res://addons/godot_servo/...")`.

### Core display components

Two primary components handle most of the integration work. Attach the appropriate script to your display node and set its `browser` property to your `ServoWebView` node. They automatically handle texture binding, coordinate transformation, input forwarding, cursor shapes, and IME anchor positioning:

| Script | Target Node & Description |
| --- | --- |
| `servo_texture_rect.gd` | Attach to a `TextureRect`. Tracks control resizing and notifies Servo once resizing settles so the page reflows properly. |
| `servo_panel_3d.gd` | Attach to a `MeshInstance3D` with a `QuadMesh` and a child `CollisionObject3D`. Manages keyboard focus arbitration between the game and web page, and projects page coordinates to screen space for IME positioning. |

### Additional utilities

These components do not make decisions on behalf of your game: setting URLs, handling `bridge_event` messages, and responding to dialogs remain the responsibility of your game code. The following helpers assist with these tasks:

| File | Description |
| --- | --- |
| `local_pages.gd` | Generates a `file://` URL for HTML pages bundled under `res://`. In exported builds, files reside inside the PCK package without direct filesystem paths, so this utility extracts them to `user://` first. |
| `select_picker.gd` | A lightweight `PopupMenu` that handles HTML `<select>` elements, as Servo does not draw dropdown menus itself. |
| `cursors.gd` | Maps CSS cursor names from the `cursor_changed` signal to Godot `DisplayServer.CursorShape` constants. (Used automatically by the components above). |
| `servo_external.gdshader` | Declares `samplerExternalOES`, required by the Android Compatibility (GLES3) path to sample external textures. `servo_external_canvas.gdshader` is the 2D CanvasItem equivalent. |

For complete implementation examples, see `demo/main.tscn` (3D panel) and `demo/flat.tscn` (2D control).

## Installation

Copy this folder into your project's `addons/` directory so it resides at `addons/godot_servo/`:

```
your-project/
  addons/godot_servo/
    godot_servo.gdextension
    bin/...
```

Keep exactly **one copy** of `godot_servo.gdextension`; duplicate manifests will cause Godot to register the extension twice. The `res://` paths inside the manifest are absolute, so libraries resolve identically regardless of location. (In this repository, the manifest sits at the project root only because the root also serves as the demo project next to `project.godot`).

## Building from source

The `bin/` directory contains compiled binaries and is not committed to git. Prebuilt release archives include these binaries; if cloning from source, run the build script once:

```sh
scripts/build.ps1     # Windows
./scripts/build.sh    # Linux and macOS
```
